27 MED tray icon symlink escape + decompression bomb

   file: src/bar/tray/watcher.rs::resolve_icon
   why:  Candidate icon path is `exists()`d (follows symlinks) then
         `std::fs::read()`d (follows again). Two attack classes:
           (a) Symlink-to-sensitive-file: a hostile icon theme or stray
               symlink in ~/.local/share/icons/ pointing to
               /etc/passwd is read + handed to image::load_from_memory
               for a decode-existence oracle.
           (b) Decompression bomb: small input PNG decodes to huge
               pixel buffer, OOM before any check fires.

   fix:  (a) safe_icon_candidate() canonicalizes candidate AND root,
             requires canonical_candidate.starts_with(canonical_root).
             Symlink escapes rejected; next candidate tried.
         (b) MAX_ICON_BYTES = 4 MB post-resolve cap, pre-decode.

   residual:  No `image::Limits` on decode — a bomb that produces huge
              output from <4 MB input still OOMs. Follow-up: switch to
              ImageReader::limits() (image 0.25 exposes it).
