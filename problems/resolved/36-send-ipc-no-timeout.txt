36 LOW send_ipc_sync has no read timeout

   file: src/main.rs::send_ipc_sync

   why:  Writes command → shutdown(Write) → read_to_string with no
         read timeout. If the bar half-closed the socket but never
         responds (SIGSTOP, deadlock, race between socket close and
         response write), the CLI process hangs forever. Affects
         --toggle, --notif-history, --screenshot (annotator IPC).

   fix:  set_read_timeout(5s). A healthy bar responds in <50ms.

   residual:  5s timeout still means a hostile bar-app can delay any
              CLI invocation by up to 5s. Acceptable — attacker must
              control the bar process itself, at which point they've
              already compromised the shell.
