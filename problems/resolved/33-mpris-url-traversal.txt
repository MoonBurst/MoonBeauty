33 LOW MPRIS file:// URL traversal in open_track_folder / trash

   file: src/libraries/backend/mpris.rs
         ::open_track_folder, ::trash_current_track

   why:  url.strip_prefix("file://") gives a path with no absolute /
         traversal check. A hostile MPRIS provider sets
           xesam:url = file://../../../home/user/.ssh/id_rsa
         The user clicks "Folder" → xdg-open ../../.. (opens /),
         or clicks "Trash"  → gio trash ~/.ssh/id_rsa (destroys key).

   fix:  safe_mpris_file_path() helper — require absolute path, reject
         "..". Applied to both sinks (open + trash).

   residual:  Attacker can still target legitimate absolute paths
              (e.g. file:///etc if user could click). But `/etc` is
              not writable so gio trash fails. Files under $HOME are
              user-owned and could be targeted via a benign-looking
              path (e.g. file:///home/u/Documents/notes.txt → user
              clicks Trash → notes.txt destroyed). Acceptable: user
              has to click "Trash" on a deliberately-named track.
