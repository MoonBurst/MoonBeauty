10 CRIT gtk-launch receives unsanitized desktop_entry
   file: src/main.rs::focus_notification_app (final fallback)
   why:  Same class as finding 01, but the victim is gtk-launch. After
         all swaymsg attempts, the code runs:
           gtk-launch <desktop_entry_cleaned>
         and if that fails:
           gtk-launch <candidates[0]>
         Neither value is validated. gtk-launch is spawned via
         Command::new (no shell) so no direct RCE, but a crafted
         desktop_entry ("--help", a path with metachars, or any value
         that matches a .desktop ID under PATH) can launch unintended
         apps. candidates[0] is app_name, fully attacker-controlled and
         frequently not a valid desktop ID.
   fix:  Apply the same app_id whitelist from finding 01 to BOTH the
         desktop_entry and candidates[*] before passing to gtk-launch.
         Reject anything that isn't ^[a-zA-Z0-9_.-]+$.
