12 MED inconsistent XDG_RUNTIME_DIR discipline
   file: src/libraries/ipc/protocol.rs          (correct: panics)
         src/overlays/lockscreen/coordinator.rs (correct: panics)
         src/overlays/notifications/ui.rs       (silent /tmp)
         src/overlays/clipboard.rs              (silent /tmp)
         src/overlays/screenshot/annotator.rs   (silent /tmp)
         src/app/update.rs                      (silent /tmp/user-<pid>)
   why:  Some modules require XDG_RUNTIME_DIR (and refuse to run
         without it), others silently fall back to /tmp. Consequences:
         (a) world-listable dir, (b) no per-user isolation, (c)
         predictable filenames enable symlink attacks. Worse: two
         codepaths may write the same logical file to different dirs
         depending on whether XDG is set (e.g. tray icon cache goes to
         /tmp/mbs-tray if XDG unset, else $XDG_RUNTIME_DIR/mbs-tray).
   fix:  Audit all XDG_RUNTIME_DIR / temp_dir() uses. Create
         src/libraries/process.rs::mbs_runtime_dir() that panics with a
         clear message if XDG_RUNTIME_DIR is unset. Replace all silent
         fallbacks.
