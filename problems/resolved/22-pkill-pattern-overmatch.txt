22 LOW pkill -f patterns match any process with that name
   file: src/main.rs::--restart-bar
         src/app/helpers.rs::kill_standalone
         src/app/update.rs (IpcCommand::Toggle(NotifSurface) respawn)
   why:  Several places invoke:
           pkill -f "target/release/moon-beauty-shell$"
           pkill -f "moon-beauty-shell --notif-surface"
           pkill -f "-sys-tooltip|-weather-tooltip|-alarm-tooltip|-tray-popup|-info-tooltip"
         The regex `target/release/moon-beauty-shell$` will also kill
         any *other* process whose argv happens to end with that string
         (a script that reads the file, a user's own debug build, an
         editor showing it). The tooltip pattern is broader still: it
         matches any process whose argv contains "-sys-tooltip" anywhere.
   fix:  Switch to killing by pidfile: write pid to
         $XDG_RUNTIME_DIR/mbs-<role>.pid on spawn, read on kill. Or add
         a unique env var (MBS_ROLE=<role>) to spawned children and
         match on it with pgrep -a. At minimum, anchor the tooltip
         pattern to the binary name:
           pkill -f "moon-beauty-shell .*-sys-tooltip"
